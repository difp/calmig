# Получение публикаций подписок: источники и ограничения

Проверено: 31 октября 2026. Задача — фотографии аккаунтов, на которые подписан пользователь личного аккаунта, в хронологическом порядке, без видео и рекомендаций. Ни один из изученных запросов пока не подтверждён как быстрый и полный источник именно такой выборки.

## Подтверждённое по исходному коду

1. Текущий адаптер `source/quiet/calendar.ts` получает страницы списка подписок и затем запрашивает публикации каждого профиля отдельно. Между началами запросов по умолчанию установлен интервал 350 мс. Поэтому время масштабируется как минимум с количеством профилей. Это свойство текущей реализации, а не гарантия лимита Instagram.
2. [ZenGram: получение подписок](https://github.com/darktekmafia/ZenGram/blob/f3613a50f730d9b31c679368b83e08b565e6842d/backend/app/services/scraper.py#L1245) реализует запрос `/api/v1/friendships/{user_id}/following/?count=200`, получая дальнейшие страницы через `next_max_id`. Это запрос **списка аккаунтов**, не пакет публикаций. Значение 200 — запрашиваемый размер, фактический размер ответа и актуальность интерфейса не подтверждены. Текущая зависимость `instagram-private-api` в `AccountFollowingFeed` параметр `count` не передаёт.
3. [instagram4j: пагинатор домашней ленты](https://github.com/instagram4j/instagram4j/blob/v3/web/src/main/java/com/instagram4j/web/paginators/FeedPaginator.java) отправляет GraphQL с параметрами `first`, `data` и `after`, читает `xdt_api__v1__feed__timeline__connection.edges` и `page_info.has_next_page/end_cursor`. Это свидетельство существования пакетной пагинации **домашней ленты** в данной реализации. Параметры именно режима Following, хронологический порядок и полнота не установлены; подставлять этот запрос в CalmIG нельзя без проверки.
4. [Zeeschuimer: обработчик Instagram](https://github.com/digitalmethodsinitiative/zeeschuimer/blob/master/modules/instagram.js) обрабатывает ту же структуру домашней ленты и отдельно распознаёт рекомендации внутри `explore_story`; [Nora: фильтр ответов](https://github.com/nonbili/Nora/blob/main/content/services/instagram.ts) удаляет узлы рекламы. Следовательно, наличие `timeline` или только сортировка по датам сами по себе не доказывают, что в ответе исключительно подписки.
5. [InstaSane](https://github.com/n3d1117/InstaSane/blob/main/Tweak.xm) переключает нативное iOS-приложение на режим `following` и использует `paginationSource = "following"`. Код не задаёт и не документирует пригодный для этого проекта формат HTTP-запроса. [Cattoclick](https://github.com/squabbled/cattoclick/blob/9cc7fa9dae24d2eb2459ebba1f51e4dd70c3c573/cattoclick.js) лишь перенаправляет браузер на `/?variant=following`, не реализуя API пагинации.

## Официальный API Meta

У Meta есть [официальная документация Instagram API](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api). В этой среде страница документации загрузилась как JavaScript-приложение без доступного текста, поэтому конкретные текущие ограничения для личного аккаунта и наличие метода выдачи подписок по ней здесь независимо не подтверждены. Нельзя считать официальный API решением для этой задачи до проверки актуальной документации и требуемых разрешений.

## Практический вывод и проверка

Самый перспективный кандидат — пакетная выдача Instagram в режиме Following, а не обход каждого профиля. Необходимо в действующей авторизованной браузерной сессии получить только технические признаки **реального** запроса режима Following и следующей страницы: имя операции, структуру параметров без токенов и персональных данных, признаки пагинации и структуры медиа. Затем сопоставить выборку с вкладкой Following, проверить удаление рекламы/рекомендаций, исключение видео и смешанных каруселей, порядок и поведение на границе семи дней. Даже после этого Instagram может вернуть неполную выборку; интерфейс должен явно это отмечать.

На ранее выполненной локальной диагностике страницы `/?variant=following` наблюдались структурированные объекты медиа, но запрос следующей страницы и принадлежность найденного блока именно к режиму Following не подтверждены. Секреты и содержимое публикаций в этот документ не записывались.

Увеличение `count` в запросе списка подписок реализовано и проверено на моках, включая короткие страницы и повторяющийся курсор. Реальный размер страниц и ускорение на аккаунте ещё не измерены; эта оптимизация не устраняет основной масштабируемый по числу аккаунтов обход фотографий.
